# InputRemap

A tiny macOS background app that remaps the buttons and wheel of a Logitech mouse,
written to replace Logi Options+ for a handful of fixed shortcuts.

Logi Options+ used ~480 MB of RAM to do this. InputRemap uses about **2.5 MB**:
no UI, no daemon fleet, no account. Just one `CGEventTap`.

> Not affiliated with or endorsed by Logitech.

## What it does

| Input | Action |
|---|---|
| Middle click (wheel press) | Mission Control |
| Hold wheel + drag ↑ | Mission Control |
| Hold wheel + drag ↓ | Launchpad |
| Hold wheel + drag ← / → | Previous / next Space (desktop) |
| Back button | Copy (⌘C) |
| Forward button | Paste (⌘V) |
| Scroll wheel | Reversed relative to the trackpad (trackpad keeps "natural" scrolling) |
| Calculator key (MX Keys S) | Opens Calculator |

Gestures fire once per press, on the dominant axis, after 60 px of travel. Anything not
listed (left/right clicks, other buttons, keyboard) passes through untouched.

The MX Keys S calculator key sends nothing to macOS on its own (in Mac mode). Options+
handled it over Logitech's HID++ channel, and so does InputRemap now: it asks the keyboard
to divert that key (feature `0x1B04`) on every connection and opens Calculator on each
press. This needs the **Input Monitoring** permission in addition to Accessibility.

Optional, via a separate script: the screenshot key on the **MX Keys S** sends ⌘⇧4
without Options+, so `scripts/configure-print-key.sh` swaps the macOS shortcuts so that
⌘⇧4 copies a region to the clipboard and ⌃⇧⌘4 saves it to a file. Undo with
`--undo`.

## Hardware

Tested with a **Logitech Lift** mouse and an **MX Keys S** keyboard, on macOS 14+ (Apple
Silicon). Other mice may report different button numbers. Run the `HardwareProbe` target
(listen-only) to see what yours sends:

```sh
swift run HardwareProbe -- --seconds 60
```

It only listens (never blocks or changes events) and logs button numbers and key codes,
not typed characters. Your terminal needs Accessibility / Input Monitoring permission.

## Requirements

- macOS 14 or later
- Swift 5.10+ (Xcode or just the Command Line Tools)
- Accessibility permission for the app (asked on first launch)

## Install

```sh
git clone https://github.com/viniborbaa/InputRemap.git
cd InputRemap
scripts/install.sh
```

This builds a release binary and installs:

- `~/Applications/InputRemap.app` (ad-hoc signed, no Dock icon)
- a LaunchAgent that starts it at login and restarts it if it dies
- logs at `~/Library/Logs/InputRemap.log`

On first run macOS asks for **Accessibility** permission. Turn it on in
*System Settings → Privacy & Security → Accessibility*; the app picks it up without
restarting.

Because the app is ad-hoc signed, the permission is tied to the exact binary. When a
rebuild changes the binary, `install.sh` resets the old permission entry and you'll be
asked again. Re-running the script with no changes keeps the permission.

The LaunchAgent label and bundle ID are `com.viniborba.inputremap`. Change `LABEL` in
`scripts/install.sh` if you fork it.

### Uninstall

```sh
scripts/install.sh --uninstall
```

## Customizing

The mappings are code, not config. Everything lives in two small files:

- `Sources/RemapCore/RemapCore.swift`: pure logic. Button numbers, gesture
  threshold, and which input produces which `Output` (`copy`, `missionControl`,
  `spaceLeft`, …).
- `Sources/RemapIO/RemapIO.swift`: turns each `Output` into the real keyboard
  shortcut or action, and reads `CGEvent`s into `Input`s.

To add a mapping, add an `Output` case, handle it in `Remapper.handle`, and send it in
`RemapIO`. Then rerun `scripts/install.sh`.

The Mission Control and Space shortcuts assume the macOS defaults (⌃↑, ⌃←, ⌃→).

## How it works

```
Sources/
  RemapCore/      pure state machine: Input → Decision(swallow?, [Output]). No macOS deps.
  RemapIO/        CGEventTap in, CGEvent shortcuts out
  InputRemap/     the executable that wires Core ↔ IO
  HardwareProbe/  listen-only event logger to discover button codes
  E2EHarness/     test window used by the end-to-end tests
  E2ESpaces/      saves/restores each display's Space around E2E runs
```

Events generated by the app are tagged (`eventSourceUserData`) so the tap ignores them
and never loops.

## Tests

Built test-first with [Swift Testing](https://github.com/swiftlang/swift-testing):

```sh
swift test --skip E2E   # unit + integration: fast, no effect on your screen
scripts/e2e.sh          # everything, including end-to-end
```

The E2E suite runs the real binary and checks real effects (the clipboard changes, the
active Space switches, Mission Control opens). It **takes over the screen for ~30 s**:
don't touch the mouse or keyboard while it runs. It needs:

- Accessibility permission for your terminal
- at least one display with 2+ regular Spaces (full-screen app Spaces don't count)

`scripts/e2e.sh` saves each display's Space and restores it afterwards, even if tests
fail.
